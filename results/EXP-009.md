# EXP-009 — How much does page-text OCR improve with more labelled pages?

**Completed 19 September 2026 · READ2016 · LightOnOCR-2-1B-base**

## Why we ran it

The [previous full-page box-and-text run](../experiments/EXP-008.md) produced unusable outputs. Before testing which *active-learning selection strategy* is best, we needed a working OCR recognition baseline and a fair reference curve. This experiment asks: **when we provide 64, 128, then 192 page transcriptions, does the model read historical pages more accurately than the untouched original model?** Pages were chosen randomly, making this the control for later model-informed selection.

## How it worked

The untouched model first predicted without any training. In each of three rounds, 64 different READ2016 TRAIN pages were selected. The dataset's existing true text simulated a human annotator: the model received the labels of selected pages only. Every round restarted from the same original model and trained on all labels acquired so far (64 → 128 → 192). The run stopped after round three, without using validation scores to decide when to stop. The measured task was **whole-page transcription**; it did not detect or score line boxes.

READ2016 provided 350 official TRAIN and 50 official VAL pages. Eight VAL pages were used to choose and check the recipe. The remaining 42 were evaluated only after the recipe was fixed. No final TEST set was used.

## What the numbers mean

**CER** (character error rate) counts character edits needed to turn the prediction into the true text, divided by the number of true characters. **WER** does the same for words. Lower is better; 0 means a perfect transcription. Rates can exceed 1 when a model adds substantial extra text. Truncated predictions count as empty, rather than being silently discarded.

On the 42 validation pages held back from recipe selection, the same four checkpoints were evaluated on the same GPU type:

| TRAIN pages labelled | CER | WER | Truncated pages |
| ---: | ---: | ---: | ---: |
| 0 — original model | 0.781 | 1.116 | 2/42 |
| 64 | 0.568 | 0.972 | 0/42 |
| 128 | 0.363 | 0.816 | 0/42 |
| 192 | **0.216** | **0.618** | 0/42 |

The maintained pipeline was also run end to end on a fixed eight-page validation slice, independently fitting and evaluating its own adapters. The 42-page pilot adapters were trained on L40S and evaluated on L4; this later runner trained on L4. These are separate executions of the same recipe, not a combined 50-page score:

| TRAIN pages labelled | CER | WER | Failed pages |
| ---: | ---: | ---: | ---: |
| 0 — original model | 0.790 | 1.269 | 0/8 |
| 64 | 0.533 | 0.943 | 0/8 |
| 128 | 0.311 | 0.777 | 0/8 |
| 192 | **0.217** | **0.625** | 0/8 |

## What we learned

On the 42-page check, character error fell by **72.3% relative to the original model**, and all 42 pages had fewer character edits at 192 labels than at zero labels. The model is learning to transcribe this historical corpus as more labelled pages are supplied. OCR is still imperfect: at 192 pages, WER is 0.618, so many words remain wrong.

This result **does not show that active learning beats random selection**—random selection is the control here. It also does not show that line-box detection works or that the model generalizes to unseen documents. READ2016's document grouping and possible overlap with model pretraining are unknown, and these pages are official validation, not an independent final test. The next experiment should compare a model-informed selector against this control at the **same page budgets**, with multiple seeds and a documented document-grouped holdout.
