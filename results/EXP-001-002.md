# EXP-001–002 — Why the first real OCR checks did not complete

**17 September 2026 · READ2016 · Qwen3-VL-4B-Instruct**

## Why we ran them

These were two-page engineering checks of the real Modal path: predict before revealing labels, select two TRAIN pages at random, fit an adapter, reload it, and evaluate the same two validation pages. They were not tests of which active-learning strategy works best.

## What happened

| Attempt | Furthest verified step | Outcome |
| --- | --- | --- |
| EXP-001 | Full-input preflight passed after correcting an initially incomplete image bundle. | The first remote base operation timed out after 600 seconds. There was no committed baseline, training, checkpoint, round or OCR score. A later CPU probe measured slow full-input hashing, but did not prove the exact stage of the original timeout. |
| EXP-002 | Base model loaded on an L40S and predicted both validation pages before training labels were revealed. | Both outputs failed: one was invalid and one truncated. CER and WER were each **1.0**. The subsequent two-page fit failed; there was no accepted adapter, reload, post-fit evaluation or completed round. |

**CER** (character error rate) and **WER** (word error rate) count edits relative to the true text; lower is better. EXP-002 scored failed outputs as empty predictions, giving 981 character edits for 981 reference characters and 151 word edits for 151 reference words. EXP-001 has no OCR metric to compare.

EXP-002's original fit call suppressed the underlying child error, so its exact cause remains unknown. A separately instrumented fit completed three optimizer updates, then failed adapter-configuration validation after saving. A small CPU reproduction found that PEFT shortened full `target_modules` paths to `["q_proj", "v_proj"]`; strict comparison rejected this equivalent configuration. This explained a reproducible validation failure and guided the next correction, without retroactively proving the original call's cause.

## What we learned

The first attempt exposed a remote-operation bottleneck; the second established that the model could load and predict remotely, while adapter acceptance still blocked a complete round. Neither attempt showed OCR improvement or an active-learning result. Both used READ2016's official 350 TRAIN / 50 VAL split for **engineering verification only**: document grouping was unknown, and no final test set was used. Existing true labels simulated annotation; these runs measured no human annotation time.

Exact run IDs, source/model versions, commands, diagnostic receipts, provisional costs and private evidence locations remain in the technical records: [EXP-001](../experiments/EXP-001.md) and [EXP-002](../experiments/EXP-002.md).
