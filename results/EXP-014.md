# EXP-014 — Development and testing of random OCR ICL

**Testing experiment completed 3 October 2026 · Report recorded 4 October 2026 · Qwen3-VL-4B-Instruct · READ2016 · L4**

## Purpose and research position

Previous experiments showed substantial improvement after fine-tuning on historical transcripts, but no consistently superior active-learning selector. The next question is whether **in-context learning (ICL)** can improve recognition by showing labelled examples at inference time, without updating model weights.

EXP-014 develops and tests that pipeline before a full comparison. **It establishes engineering readiness on a small diagnostic sample; it does not establish an ICL benefit or equivalence to fine-tuning.** Full validation inference has not run.

## Setup and how the pipeline works

- **Task:** transcribe READ2016's supplied text-line crops in original reading order. Locations are known; the model predicts text, not boxes.
- **Model:** the pinned original Qwen3-VL-4B-Instruct used in EXP-012/013, without an adapter. The crop processing, transcription instruction and greedy decoding remain unchanged: eight-pixel padding, maximum edge 1024, BF16, repetition penalty 1.1 and at most 64 generated tokens.
- **Demonstration bank:** the exact EXP-013 random seed-824 first-round selection: **24 TRAIN pages / 589 labelled lines**. Page membership is reused from saved evidence rather than regenerated.
- **Prompt conditions:** 0, 8 or 24 crop/transcript pairs, followed by one unlabelled query crop. Each query has a reproducible random draw without replacement; its eight-shot examples are the first eight of its 24-shot draw. Different queries can share examples. Validation transcripts never enter the prompt.
- **Evaluation:** restore source order, then compute character error rate (CER) and word error rate (WER) locally against held-out transcripts. Both are edit counts divided by reference length; lower is better, and values above 1 are possible.

**Selected TRAIN crops + transcripts → random paired demonstrations → unlabelled VAL crop → original-model transcription → local evaluation.** No training takes place during ICL.

The existing [region runner](../src/active_ocr/region_pipeline.py) now supports explicit `prepare`, `check` and `evaluate` stages, with a small [ICL module](../src/active_ocr/icl.py) and [frozen recipe](../experiments/recipes/read2016-known-box-icl.json). Saved contexts and predictions support resumption. Full evaluation requires a matching passed readiness check. No new dependencies or second OCR runner were added.

## What was verified

- Twelve focused local cases passed, covering example pairing, TRAIN/VAL isolation, deterministic sampling, receipt provenance, cache identity/checksums and readiness/CLI guards.
- The actual processor produced unchanged zero-shot and supervised-training input tensors compared with the previous implementation. Existing GPU training was not repeated.
- Historical original-model and 24-page LoRA predictions were recomputed locally; their metrics matched exactly. The reused adapter's weights matched the executed receipt hash.
- An L4 check transcribed **eight lines, one from each of eight validation pages**, at all three shot counts: **24 outputs**. Lines were chosen by crop geometry, alternating wide and narrow cases. The largest actual 24-shot input ran first.
- Image counts, context limits, saved identities and output coverage passed. Local replay of the existing 861-line baseline verified aggregation order and duplicate rejection; that replay was not new GPU inference.

An earlier 24-output check was preserved before the final CLI guard, then the same small check was repeated for the final code. **48 diagnostic generations occurred in total; this is not a repeated-seed study.**

## Diagnostic results — eight lines only

All three conditions use the same **132 reference characters / 19 words**.

| Examples per query | CER | WER | Maximum input tokens | Capped / empty outputs |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 0.765152 | 0.947368 | 185 | 0 / 0 |
| 8 | 0.757576 | 1.000000 | 1412 | 0 / 0 |
| 24 | 0.757576 | 0.894737 | 3935 | 0 / 0 |

Twenty-four examples require **25 images including the query**. The largest tested input plus the 64-token output allowance totals **3,999 tokens** and ran successfully on L4. Peak reserved GPU memory was **9.58 GiB**; this includes retained allocator cache and is a capacity check rather than an independent memory benchmark.

Adding demonstrations reduced character edits from 101 to 100 on this tiny sample; word errors varied. These differences cannot establish a reliable improvement. The main finding is that crop/transcript prompting, generation, recording and evaluation worked for the tested inputs. The full run retains per-query context and memory checks.

## Next stage and limits

EXP-014 remains this completed **development/testing experiment**. The subsequently approved [EXP-015](EXP-015.md) completed the separate full eight/24-shot study across all 861 lines (**1,722 new predictions, zero fits**). Its report compares the checked historical controls; its separate namespace preserves EXP-014's testing evidence.

The intended study is one bank and one previously examined official-validation slice. Writer/document grouping and pretraining overlap remain unknown, and the historical LoRA checkpoint is one realized fit with an initialization limitation. Neither this test nor the planned pilot can establish independent generalization, repeatable annotation savings or box detection.
