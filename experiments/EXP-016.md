# EXP-016 — What do random OCR demonstrations contribute?

**Completed and independently audited 4–5 October 2026.** Frozen implementation `18019c916d6c84d4a0b289ef8840db24fb0c5cbb`; all 4,228 new outputs and 37 serial L4 calls completed. All three apps are stopped/zero tasks.
Reader interpretation: [results/EXP-016.md](../results/EXP-016.md).

## Question and predeclared design

EXP-015 improved modestly with random crop/transcript demonstrations, removed many unexpected
script outputs, and remained far behind the saved 24-page LoRA checkpoint. Its approved decoder
follow-up retained repetition penalty 1.1. This study isolates demonstration content before adding
retrieval, larger models or more training. Are correct visual/text associations necessary for the
observed benefit, or can unpaired textual context explain a substantial part?

Reuse the pinned Qwen3-VL-4B-Instruct, READ2016 line boxes/crops, seed 824 and exact EXP-013 random
bank of 24 TRAIN pages / 589 lines. For each validation query, draw 24 distinct bank lines by the
existing deterministic query sampler; eight-shot is the same draw's prefix. All conditions use
identical transcript order. The unlabelled query crop is always the final user input.

| Condition | Demonstration images | Demonstration transcripts |
| --- | --- | --- |
| Correct paired reference | Original associated crops | Original source labels |
| Text-only control | Removed; query image retained | Same labels in the same order |
| Mismatched control | Cyclically rotate the sampled crops left by one | Same labels in the same order |

Mismatched pairs retain the exact image and transcript multisets and have no fixed line-ID
associations. Duplicate transcripts can still match after permutation; count these explicitly.
Text-only changes image context length as well as grounding. Neither contrast alone proves the
model cannot use visual examples or that it learns new glyph mappings.

## Frozen settings and measures

[Study specification](recipes/read2016-known-box-icl-controls.json) inherits the unchanged
[base recipe](recipes/read2016-known-box-icl.json): Qwen revision
`ebb281ec70b05090aa6165b016eac8ec08e71b17`, RGB eight-pixel padded supplied-box crops, longest
edge 1024 preserving aspect ratio, original transcription prompt, BF16, greedy generation,
64 new tokens, repetition penalty **1.1**. Fresh independent conversation per query; no fitting
or adapter loading. Validation labels stay only in the local evaluator.

Primary **line-text-nfc-raw-v1** measures corpus character/word edits aligned within each fixed
source line, with NFC normalization and every saved capped output retained. The inherited decoder trims outer whitespace and replaces newlines with spaces; “raw” here means before cap masking, not unprocessed decoder bytes. CER/WER denominators
are reference characters/words, not mean per-line rates. Secondary historical page-text-nfc-v1
joins lines in source order and scores length-capped lines as empty, matching previous reports.
Historical scores are not rewritten. Report both metrics, empty/capped outputs, actual EOS/length
termination for new rows, unexpected Cyrillic lines, input/visual tokens and peak memory.

Original zero-shot, paired 8/24-shot and 24-page LoRA outputs are checked/reused, never relabelled
as new inference. Recompute every primary and secondary score; preserve the original receipt,
file hash and executed recipe identity. The LoRA comparison is the realized EXP-013 adapter
with its historical pre-construction seeding limitation, not a fresh controlled mean.
