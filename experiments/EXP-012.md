# EXP-012 — READ2016 known-box region recognition

**Status: running.** This is a separate active-learning pipeline. It asks whether selecting READ2016 pages for **text recognition with known line locations** improves transcription over random selection. The recognizer receives a crop of each supplied PAGE-XML `TextLine` box and returns text only. Boxes and reading order are supplied from the source; this experiment does **not** test line detection. The existing whole-page Qwen and LightOnOCR runners and EXP-009–011 results are unchanged.

## Frozen method

- Source: READ2016 v1.2.0, frozen source run `781d319efaa94b68bdd8027a2ae4e01c`, manifest SHA-256 `ac0a02a218a2142c6ee92ae964e7828ddfc65545dd6ca12f695815bb4493bdd6`; 350 official TRAIN pages (8,367 line boxes) and 50 official VAL pages (1,043 boxes). Document grouping and possible model-pretraining overlap are unknown. No final TEST result.
- Geometry: source PAGE reading order, preserved by the prepared manifest. Each axis-aligned line box is cropped from the original full-resolution JPEG with eight pixels of clamped padding. The model never predicts box coordinates. Original full-page text order is reconstructed from region transcriptions in source order. Empty or capped region outputs remain empty for text scoring; the number of such regions is reported separately.
- Model: Qwen3-VL-4B-Instruct revision `ebb281ec70b05090aa6165b016eac8ec08e71b17` from the existing pinned input Volume. [The isolated recipe](recipes/read2016-known-box-regions.json) fixes a 1,024-pixel crop edge, 64-token greedy output cap, one epoch, BF16 LoRA rank 8/alpha 16, learning rate 1e-4, batch size one and four-step accumulation. Every fit resets from the same base on all selected TRAIN lines. The different one-epoch crop recipe makes this a new task, not a matched model-input comparison to EXP-011.
- Acquisition unit and budget: whole TRAIN pages, 0/64/128/192 selected pages across three rounds, seeds 824–826. The seed-matched original-model and first 64-page random checkpoints are reused by entropy, least confidence and k-center. Random selects without model scores. For uncertainty, three fixed line positions (25%, 50%, 75%) per candidate page are scored without ground-truth text; page entropy or confidence is the mean of the three crop scores. K-center greedily covers the normalized mean of three Qwen crop-visual features per page. Selection remains page-level. The three-crop proxy is predeclared to bound L4 acquisition cost; it is not full-page uncertainty.
- GPU: Modal L4 for fit, validation inference and acquisition scoring; app `fyp-read2016-known-box-regions`, input bundle `94ed4f7f79d5d1110b7454c12a3b86d643cdb9dc0dece83d63734c2e4d87dcb6`. At the 2026-09-25 [Modal list rates](https://modal.com/pricing), L4 is USD 0.000222/s and L40S is USD 0.000542/s before billed CPU and memory. More crop-level work can still make total spend higher; report observed charges after the run rather than equating a lower GPU rate with a lower experiment bill.
- Evaluation: original official VAL42 pages, excluding the recipe's eight engineering-check VAL pages. Local `PageTextEvaluatorV1` reports corpus CER and WER from reconstructed ordered lines. Validation reference text stays with `LocalOracle`; only selected TRAIN transcripts reach remote fitting, and scoring records contain image address, dimensions and known geometry only. Annotations are simulated by revealing frozen true labels for selected pages.

## Evidence and artifacts

The implementation is [`src/active_ocr/region_pipeline.py`](../src/active_ocr/region_pipeline.py). Pilot receipts are ignored under `.local/verification/region-ocr/`. The full-study run directory is `.local/verification/region-ocr-v2/`, with per-run `recipe.json`, `round-N.json` and selection artifacts and a shared identity-keyed `_score-cache/`. Its local `run-all.zsh` executes one Modal L4 run at a time and stops on failure. Modal originals go under `/output/<run-name>/round-N/` on output Volume `vo-J6KGzVVUq9jFE6mJFHO1PJ`. Each new adapter will be hash-verified and mirrored under ignored `.local/models/exp-012/<strategy>/seed-<seed>/round-<N>/adapter/`, with exact identities recorded here after completion. The base model remains in `.local/assets/qwen3-vl-4b-ebb281e/`; the prepared dataset remains in `.local/prepared/read2016-v1-8db5833/` and original source archive in `.local/assets/read2016-1.2.0/`.

The first feasibility pilot used a 128-token output cap; its reference-line tokenizer audit found a maximum of 22 text tokens across all 9,410 source lines. The production recipe therefore caps at 64 tokens to limit runaway generations while leaving ample room for a correct line. The one-page L4 uncertainty probe passed on [Modal](https://modal.com/apps/bowenbryant24/main/ap-tDFR5NzeKm6vwW5mWOJ8Vb): three crop generations produced finite entropy `0.11237` and confidence `0.49346`, with no reference text sent. A local focused test checks crop bounds, source order and exclusion of targets from unlabelled records. The [full original-model VAL42 baseline](https://modal.com/apps/bowenbryant24/main/ap-XWzkdlqlFj45Kcu3cgnYvE) completed on L4: 42 pages, 861 ordered regions, CER `0.8096` (14,344 edits / 17,718 reference characters), WER `1.0950` (2,929 / 2,675 words), one capped region. Its raw receipt and predictions are in ignored `.local/verification/region-ocr/region-random-seed824/round-0.json`; no adapter exists at stage 0. This is an original-model recognition baseline, not active-learning evidence. The [first 64-page pilot fit and VAL42 run](https://modal.com/apps/bowenbryant24/main/ap-UwVkj8v2SdDFouH945LrCN) completed on L4: 1,537 selected TRAIN line crops, one epoch, 385 optimizer steps, CER `0.1887` and WER `0.5742` on the same 861 VAL42 regions, with zero capped regions. The raw receipt is `.local/verification/region-ocr/region-random-seed824/round-1.json`. Its LoRA weights are at Modal `/output/region-random-seed824/round-1/adapter/` and in verified ignored mirror `.local/models/exp-012/pilot/random/seed-824/round-1/adapter/`; `adapter_model.safetensors` SHA-256 is `f8a16737870df0d38a9060b0ab0410dc3594c850804b3fd487ecab2270116a11` in both receipt and local mirror. Pilot runner commit `3696d3e` and its saved `recipe.json` bind the 128-token protocol. The production runner commit is `9a4bac4` with the separate 64-token recipe and run namespace; it has not produced comparison results yet. This pilot shows that known-box crop recognition learns from selected labels, not that one page-selection strategy beats another.
