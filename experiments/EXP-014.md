## Purpose and frozen setup

Verify the pipeline for testing original Qwen OCR with 0/8/24 random demonstrations against
the existing 24-page fine-tuned reference; only the bounded readiness check ran. Use READ2016
v1.2.0 supplied line crops, not detection. Exact EXP-013 seed-824 random bank:
24 TRAIN pages / 589 labelled lines. Each query gets reproducibly sampled distinct crop/transcript
pairs; eight-shot is the prefix of its 24-example draw. Query truth stays in the local evaluator.

Qwen3-VL-4B-Instruct revision `ebb281ec70b05090aa6165b016eac8ec08e71b17`; unchanged prompt,
eight-pixel padding, 1024 longest edge, BF16, greedy 64-token generation and repetition penalty 1.1.
L4, 2 CPUs, 32 GiB host memory; existing Transformers/PyTorch and volumes. No fitting, retrieval,
additional seeds or faithfulness analysis. The available annotation bank is 24 pages for both methods,
even though ICL sees a subset per prompt. No comparative cost advantage is assumed.

- `region_pipeline.py` adds `--icl-stage prepare/check/evaluate` and paired examples to its shared
  input builder; existing modes remain supported. An ICL recipe requires an explicit stage and
  rejects conflicting `--prepare-only` flags before cloud work or accidental fitting.
- `icl.py` checks bank/control provenance, assembles deterministic nested contexts, uses the existing
  L4 runtime and evaluator, saves resumable query/chunk receipts, and restores source reading order.
  Full evaluation requires matching completed readiness. No dependencies or separate OCR runner added.
- Twelve focused cases passed: seven ICL cases and five existing region cases. They cover pairing,
  TRAIN isolation, deterministic nested samples, cache identity/checksum rejection, receipt-origin
  checks, readiness gating and CLI ambiguity. Lint/whitespace checks passed.
- The real local processor produced identical zero-shot inference and supervised-training tensors
  to the frozen legacy input function. GPU training was not repeated. Evidence is in the preserved
  `readiness-before-cli-guard/legacy-input-parity.json`.
- Both controls below were recomputed from their saved 861-line predictions; exact integer counts
  and CER/WER match. The 24-page adapter's weight hash matches its executed receipt. The corrected
  EXP-013 receipt is a copy: its original execution path and file hash are checked before reuse.
- Final L4 check generated eight geometry-selected VAL8 crops at each context size: 24 outputs.
  The largest actual 24-shot prompt ran first. All image/visual-token counts, context limits,
  image/source hashes and output coverage passed; no OOM, capped or empty output occurred.
- `audit.json` recomputes the small-check metrics and verifies every saved context. It also replays
  full 861-line aggregation from existing original predictions in reversed order, reproduces exact

prefill/decode, excluding CPU preparation/loading. These eight-line scores cannot establish an ICL gain.

check was repeated for the final code identity. Total diagnostic generations: **48**, with one bank,
seed and context draw. No full validation or new training occurred; both apps completed and stopped.
