# EXP-017 — LightOnOCR replication of random OCR ICL and content controls

**Implementation and verification in progress, 5 October 2026.** This record is the frozen
protocol and subsequent technical evidence. Reader interpretation: [results/EXP-017.md](../results/EXP-017.md).

## Purpose and fixed design

Replicate EXP-015's paired demonstrations and EXP-016's content controls with the original
**LightOnOCR-2-1B-base** used in EXP-009 (revision `c1bc8eb6625be7b34178ff53481b242f7b8ffcb8`).
Ask whether their modest ICL benefit and sensitivity to wrong visual associations transfer from
Qwen3-VL-4B-Instruct to an OCR-specialized 1B model. Neither improvement nor inferiority is assumed.

Use the same frozen READ2016 supplied line boxes; seed 824; the same 24 TRAIN pages / 589-line
bank; identical deterministic per-query draws, with eight-shot the prefix of 24-shot. Each fresh
conversation ends in one unlabelled query crop. Query truth stays in the local evaluator.

| Condition | Demonstrations | Shots |
| --- | --- | --- |
| Zero-shot | None | 0 |
| Paired | Correct crop and source transcript | 8 / 24 |
| Text-only | Same transcripts and turn order; demonstration images removed | 8 / 24 |
| Mismatched | Same transcripts; demonstration crops cyclically rotated left by one | 8 / 24 |

A **fresh crop-level LightOnOCR zero-shot baseline** is necessary: EXP-009 used whole pages,
not these line crops. EXP-015/016 Qwen predictions are references with original provenance;
no Qwen inference is rerun. EXP-009's page-trained adapters are not matched 24-page crop controls,
and no LightOnOCR fitting, new adapter, retrieval, seed or decoder sweep is included here.

## Frozen settings and model compatibility

[Specification](recipes/read2016-known-box-icl-lighton.json) inherits the Qwen crop recipe:
original RGB box crop plus eight-pixel padding, longest edge 1024 preserving aspect ratio,
`Transcribe only the text in this cropped line. Return only the transcription.`, original chat
template, BF16, greedy generation, 64 new tokens and repetition penalty 1.1. Only model-specific
native processor/tokenizer and model weights differ. Model-selected image-token expansion is
necessarily different. Do not claim equal tokens or equal model capability from equal shots.

LightOnOCR's [author paper](https://arxiv.org/html/2601.14251v1) describes prompt-free OCR training;
[its model card](https://huggingface.co/lightonai/LightOnOCR-2-1B-base) demonstrates one image.
Its pinned chat template serializes all image/text turns, and installed Transformers supports
multiple images. Verify actual serialized targets, image placeholders and pixel order before GPU.
Using the same Qwen instruction tests this fixed protocol, not LightOnOCR's optimized native
inference. Architectural acceptance alone is not evidence of trained ICL competence.

Primary `line-text-nfc-raw-v1`: corpus character/word edits aligned within fixed source lines,
NFC-normalized, retaining every saved capped output. Decoder outer whitespace trimming and
newline-to-space replacement are the inherited conventions. Secondary `page-text-nfc-v1`:
join lines in reading order and replace capped lines by empty text, for historical compatibility.
Report both definitions, caps/empty outputs, EOS/length termination, unexpected Cyrillic,
context sizes and pair-mismatch integrity. Do not silently choose the more favourable metric.

## Gates and bounded execution

1. Focused CPU checks: Qwen regression, LightOn image-token capacity and receipt identity;
   real pinned processor checks of target/image order; source/bank hashes and blind validation.
2. L4 diagnostic: eight original check queries across seven conditions, 56 outputs. Largest actual
   24-shot prompt first. Verify native model loading, every image, context capacity and saved tokens.
3. VAL8 pilot: all 182 lines / seven conditions, 1,274 outputs. Gate on integrity, not OCR scores.
4. VAL42: all 861 lines / seven conditions, 6,027 outputs, after both gates. Locally recompute and
   independently audit metrics, tokens, contexts, source/model hashes and cross-model references.

Bound **7,357 new outputs / at most 54 serial calls / three apps**, L4 only, CPU 2, memory
32768 MiB, same resumable 64-query chunks and existing input/output Volumes. Shared pinned model
cache is retained on the output Volume; verify processor and weight hashes in every chunk.
No additional paid smoke, parallel workers, budget-limit changes or unrequested training.
Pause on integrity failure or materially unexpected resources and preserve failed/partial attempts.
